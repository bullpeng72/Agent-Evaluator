Retrieval vs Generation 메트릭

단계 메트릭 목표 개선 방법
Retrieval Context Recall > 0.8 Vector DB, 임베딩 모델 개선
Retrieval Context Precision > 0.8 필터링, 랭킹 알고리즘 강화
Generation Faithfulness > 0.9 프롬프트 개선, Temperature 조정
Generation Answer Relevancy > 0.9 질문 이해, Context 선택 개선

✅ RAG 최적화 체크리스트

  • Context Recall 낮음: 검색 알고리즘 개선 (BM25 → Dense Retrieval)
  • Context Precision 낮음: 필터링 강화, Top-K 조정
  • Faithfulness 낮음: LLM 프롬프트에 "Context 기반 응답" 명시
  • Answer Relevancy 낮음: 질문 리라이팅, Context 가중치 조정

5가지 Tool Selection 패턴

패턴 Precision Recall F1 문제점
Perfect 100% 100% 100% 없음 (이상적)
Over-Selection 25% 100% 40% 불필요한 도구 선택 (비효율)
Under-Selection 100% 33% 50% 필수 도구 누락 (미완성)
Wrong Selection 0% 0% 0% 완전히 잘못된 선택
Partial Overlap 50-67% 50-100% 67% 일부 맞고 일부 틀림

💡 Layer 1 vs Layer 2 Tool Metrics

  • Layer 1 (Tool Efficiency): 실행 효율성 - 중복, 실패율, 실행 시간
  • Layer 2 (Tool Selection): 선택 정확도 - 올바른 도구 선택 여부

Layer 2 Security Metrics (2개)

🔐 Privilege Escalation Detection

  • 초기 권한 → 최종 권한 추적
  • 의심스러운 권한 전환 시퀀스
  • 위험도 스코어 (0-10)
  • 권한 레벨: read, write, execute, admin

⚔️ Attack Pattern Detection

  • Data Exfiltration (데이터 유출)
  • Lateral Movement (측면 이동)
  • Defense Evasion (방어 회피)
  • 신뢰도: 0.0 ~ 1.0

Layer 1 vs Layer 2 Security

구분 Layer 1 Security Layer 2 Security
탐지 대상 입력/출력/권한 위반 권한 상승, 도구 체인 공격
분석 단위 단일 요청/응답 다중 도구 호출 시퀀스
복잡도 낮음 (패턴 매칭) 높음 (행동 분석)
적용 시기 모든 에이전트 Multi-tool 에이전트
위협 유형 SQL injection, XSS Data exfiltration, Lateral movement

🚨 보안 임계값 권장사항

  • Escalation rate: ≤ 2% (권한 상승 2% 이하)
  • Detection rate: ≥ 95% (공격 탐지율 95% 이상)
  • Data exfiltration attempts: = 0 (데이터 유출 0건)
  • High risk events: = 0 (고위험 이벤트 0건)

API 1: 환각 유형별 분석

from agent_evaluator import PerformanceMonitor evaluator = PerformanceMonitor() # 환각 탐지 evaluator.hallucination_detector.detect_hallucination( task_id="medical_query_1", response="Temperature is 105°F, take 5000mg aspirin", context="Normal: 98.6°F, Safe dose: 325-650mg", ground_truth="Normal: 98.6°F" ) # 🎯 고급 API 사용 breakdown = evaluator.hallucination_detector.get_hallucination_by_type() print(f"전체 환각: {breakdown['total_hallucinations']}") print(f"숫자 오류: {breakdown['numerical_errors']}") print(f"시간 오류: {breakdown['temporal_errors']}") print(f"검증되지 않은 주장: {breakdown['unsupported_claims']}")

✅ 활용 예시

  • 숫자 오류 多: 프롬프트에 "정확한 숫자 사용" 지시 추가
  • 시간 오류 多: 시간 정보 사실 확인 강화
  • 검증되지 않은 주장: Context 기반 응답 유도

14. Troubleshooting & FAQ

Common Issues

❌ 문제: Layer 3 API Key 오류

원인: OpenAI API 키 미설정

해결:

# .env 파일 생성 OPENAI_API_KEY=sk-... # 또는 환경 변수 설정 export OPENAI_API_KEY=sk-...

⚠️ 문제: Layer 3 비용이 너무 높음

원인: gpt-4 사용 또는 대량 평가

해결:

  • gpt-4o-mini 사용 (90% 절감)
  • 샘플링: 전체의 10-20%만 평가
  • 캐싱: 동일 Context 결과 재사용

⚠️ 문제: Tool Selection F1이 낮음

원인: expected_tools 정의 부족 또는 Agent 성능

해결:

  • Golden Dataset에 expected_tools 명시
  • Agent 프롬프트에 도구 사용 가이드 추가
  • 도구 설명(description) 개선

FAQ

Q1: Layer 2와 Layer 3의 차이는?

A: Layer 2는 무료 로컬 계산 (Agentic + Security), Layer 3는 LLM 기반 유료 평가 (DeepEval + Ragas)입니다. Layer 2는 빠르지만 정확도 ~70%, Layer 3는 느리지만 정확도 ~90%입니다.

Q2: Golden Dataset은 몇 개가 적절한가요?

A: 최소 5개 (테스트), 권장 100개 (통계적 신뢰도), 이상적 1000개 (프로덕션)입니다.

Q3: 고급 API는 언제 사용하나요?

A: 기본 메트릭으로 문제를 발견했을 때, 더 깊이 있는 분석이 필요한 경우 사용합니다. 예: Hallucination이 높음 → get_hallucination_by_type()으로 유형 분석 → 숫자 오류가 많음 → 프롬프트에 "정확한 숫자" 지시 추가

Q4: Layer 2 Security는 필수인가요?

A: Multi-tool Agent나 프로덕션 환경에서는 필수입니다. Layer 1 Security는 단일 요청/응답 검증, Layer 2 Security는 복잡한 도구 체인 공격 탐지를 담당합니다.
