Example 03: TaskResult Helpers 🛠️

03_taskresult_helpers.py
FREE LAYER 1 DEMO

💾 JSON 파일 생성: ❌ 없음

이 예제는 Helper 함수 사용법 데모가 목적이므로 JSON 파일을 생성하지 않습니다. 콘솔 출력으로 동적 계산 결과를 확인할 수 있습니다.

목표: 하드코딩 없이 TaskResult의 모든 필드를 동적으로 계산하여 평가 정확도를 향상시킵니다.

❌ 잘못된 방식: 하드코딩

task = TaskResult( task_id="bad_001", task_type=TaskType.QA.value, success=True, completion_score=1.0, # ❌ 하드코딩! accuracy_score=0.85, # ❌ 추측값! execution_time=1.5, tokens_used={"total": 100}, # ❌ 추정값! # ... )

문제점:

  • completion_score=1.0 → 실제 완료도가 아닐 수 있음
  • accuracy_score=0.85 → 근거 없는 추측값
  • tokens_used → 실제 API 응답과 다름
  • 유지보수 어려움, 일관성 없음

✅ 올바른 방식: 동적 계산

from agent_evaluator.helpers.taskresult_helpers import ( create_taskresult_from_execution ) task = create_taskresult_from_execution( task_id="good_001", task_type="qa", question="한국의 수도는?", response="대한민국의 수도는 서울입니다.", ground_truth="서울", execution_time=1.2 ) # ✅ 자동으로 계산됨: # - completion_score: 길이, 유사도 기반 자동 계산 # - accuracy_score: 4가지 유사도 메트릭 조합 # - tokens_used: 실제 텍스트 기반 추정

장점:

  • 완료도, 정확도 자동 계산으로 객관성 보장
  • 토큰 수 실제 텍스트 기반 추정
  • 일관성 보장, 재현 가능
  • 유지보수 용이

🔧 Helper 함수 목록

  • calculate_completion_score(): 응답 길이, 에러, 유사도 기반 완료도 계산 (0.0 ~ 1.0)
  • calculate_accuracy_score(): 4가지 유사도 메트릭 가중 평균 (Token Overlap 40%, Jaccard 30%, LCS 20%, Character 10%)
  • estimate_tokens(): 텍스트 길이 기반 토큰 수 추정 (영어: 문자/4, 한국어: 문자/2)
  • extract_tokens_from_openai(): OpenAI API 응답에서 토큰 수 추출
  • extract_tokens_from_langchain(): LangChain 응답에서 토큰 수 추출
  • create_taskresult_from_execution(): 위 모든 함수를 통합한 완전 자동 생성

Example 04: Thresholds & Validation ✅

04_thresholds_validation.py
FREE LAYER 1

목표: 임계값(Thresholds) 시스템을 활용하여 Pass/Fail 자동 판정 및 품질 게이트를 구현합니다.

🎯 임계값이란?

임계값은 각 메트릭의 합격 기준입니다. 품질 게이트(Quality Gate) 역할을 하여 배포 가능 여부를 자동으로 판단합니다.

예시:

  • TCR ≥ 90% → 합격 (Pass) → 배포 가능
  • TCR < 90% → 불합격 (Fail) → 배포 중단
  • Hallucination ≤ 5% → 합격

임계값 설정 예제

monitor.thresholds = { # ========== 높을수록 좋은 지표 (≥) ========== 'tcr': 90.0, # TCR ≥ 90% 'accuracy': 85.0, # Accuracy ≥ 85% 'quality': 7.0, # Quality ≥ 7/10 'tool_efficiency': 80.0, # Tool Efficiency ≥ 80% # ========== 낮을수록 좋은 지표 (≤) ========== 'hallucination': 5.0, # Hallucination ≤ 5% 'latency': 3.0, # Latency ≤ 3초 'cost_per_task': 0.10, # Cost ≤ $0.10 # ========== 보안 메트릭 ========== 'threat_rate': 5.0, # Input Threat ≤ 5% 'leakage_rate': 1.0, # Output Leakage ≤ 1% 'compliance_rate': 98.0, # Authorization ≥ 98% }

임계값 비교 및 판정

# 평가 데이터 기록 후... comparison = monitor.compare_with_thresholds() # Pass/Fail 카운트 pass_count = sum(1 for m in comparison.values() if m['status'] == 'pass') fail_count = sum(1 for m in comparison.values() if m['status'] == 'fail') # 결과 출력 for metric_key, result in comparison.items(): status_icon = "✅" if result['status'] == 'pass' else "❌" direction = "≥" if result['direction'] == 'higher' else "≤" print(f"{status_icon} {result['name']}: {result['value']:.2f} {direction} {result['threshold']:.2f}") # 최종 판정 overall_pass = fail_count == 0 print(f"\n최종 판정: {'✅ PASS - 배포 가능' if overall_pass else '❌ FAIL - 개선 필요'}")

✅ 실행 결과 예시

✅ TCR: 95.0% ≥ 90.0% ✅ Accuracy: 87.5% ≥ 85.0% ✅ Hallucination: 2.3% ≤ 5.0% ❌ Quality: 6.5 < 7.0 ✅ Latency: 2.1초 ≤ 3.0초 ✅ Cost: $0.08 ≤ $0.10 Pass: 5개 | Fail: 1개 최종 판정: ❌ FAIL - 개선 필요 (Quality 개선 후 재평가)

📊 임계값 최적화 전략

  • 데이터 기반 설정: 최소 100개 Task 평가 후 P90/P95 백분위수 사용
  • 환경별 차등: Dev(70%) < Staging(85%) < Prod(95%)
  • 지표별 우선순위: 필수(TCR, Hallucination) / 권장(Accuracy, Quality) / 참고(Latency, Cost)
  • 지속적 개선: 매월 검토 및 조정, 성능 향상 시 임계값 상향

🎯 6가지 고급 분석 메서드

  • Prompt Injection: "ignore previous instructions"

⚠️ 비정상 전이 유형

  • 무한 루프: failed → retrying → failed (반복)
  • Dead-end 상태: cancelled → * (종료 상태에서 전이)

Troubleshooting & FAQ

자주 발생하는 문제

❌ 문제: 데이터가 Dashboard에 안 보임

해결 방법:

  1. 파일이 Dashboard/data/evaluation_results/에 저장되었는지 확인
  2. Dashboard 새로고침 (F5)
  3. 사이드바에서 파일 다시 선택

❌ 문제: Hallucination Rate가 100% 초과

원인: 하나의 응답에 여러 환각이 탐지되어 평균이 100% 초과

해결: 정상 동작입니다. 환각 건수를 참조하세요.

⚠️ 문제: 품질 점수가 모두 0

원인: get_quality_metrics() 반환 키가 예상과 다름

해결: dimension_averages 딕셔너리에서 각 차원 추출

quality_metrics = monitor.quality_evaluator.get_quality_metrics() dim_avg = quality_metrics['dimension_averages'] print(f"Relevance: {dim_avg['relevance']:.2f}/5.0")

FAQ

Q1: API 키가 필요한가요?

A: Level 1 Foundation은 100% 무료이며 API 키가 전혀 필요 없습니다. Layer 3 (DeepEval, Ragas)만 API 키가 필요합니다.

Q2: 최소 몇 개의 Task를 평가해야 하나요?

A: 최소 5개 이상 권장하며, 통계적 유의성을 위해 100개 이상이 이상적입니다.

Q3: 프로덕션에서 사용할 수 있나요?

A: 네! 임계값 시스템과 자동 판정 기능으로 CI/CD 파이프라인에 통합 가능합니다.
