# Agent-Evaluator SDK 강의계획서

**과정명:** AI 에이전트 평가 실무 — Agent-Evaluator SDK 완전 가이드
**버전:** v0.6.1 기준
**총 시간:** 16시간 (5모듈)
**형태:** 개념 설명 → 코드 분석 → 실습 → 대시보드 확인 반복

---

## 강의 개요

| 항목 | 내용 |
|------|------|
| 대상 | AI 에이전트를 개발하거나 품질관리하는 실무자 |
| 전제 수준 | Python 기초, LLM/에이전트 개념 이해 (프레임워크 경험 있으면 유리) |
| 수강 형태 | 5개 모듈 독립 수강 가능 (순서대로 수강 권장) |
| 실습 환경 | Python 3.8+, pip, 텍스트 에디터 |
| API 키 | Module 4만 OPENAI_API_KEY 필요 |

## 사전 준비 사항

### 환경 설치

```bash
# 1. 저장소 클론
git clone [repo] && cd Agent-Evaluator

# 2. 기본 설치 (Module 1–4)
pip install -e ".[llm,serve]"

# 3. Layer 3 포함 (Module 4)
pip install -e ".[all]"

# 4. .env 파일 설정
cp Evaluator_Examples/.env.example Evaluator_Examples/.env
# → Evaluator_Examples/.env 에 API 키 입력

# 5. 설치 확인
agent-eval check

# 6. 대시보드 테스트
agent-eval serve --port 8765
```

### `.env` 필드 설명

```bash
# Module 1-4: 불필요 (Layer 1/2는 API 키 없이 동작)
OPENAI_API_KEY=sk-...          # Module 4 (Layer 3) 필수
ANTHROPIC_API_KEY=sk-ant-...   # 선택 (ClaudeHelper 사용 시)
LANGCHAIN_TRACING_V2=false     # Ragas 사용 시 false 권장
AGENT_EVALUATOR_OUTPUT_DIR=./results
```

## 모듈별 강의 계획 상세

### Module 1 — 에이전트 평가의 필요성과 SDK 전체 구조 (2h)

**학습 목표:**
1. 전통 소프트웨어 테스트와 AI 에이전트 평가의 차이를 설명할 수 있다
2. 3-Layer 구조와 16개 트래커의 역할을 파악할 수 있다
3. `PerformanceMonitor`와 `TaskResult`를 직접 코딩할 수 있다
4. 대시보드를 실행하고 6개 탭의 목적을 이해할 수 있다

**시간 배분:**
- 1-1. 왜 어려운가 + 실패 유형 4가지: 30분
- 1-2. 아키텍처 + TaskResult + create_taskresult: 45분
- 1-3. 환경 설정 + 대시보드 첫 실행: 45분

**참조 Docs:** `01_README.md`, `04_LEARNING_GUIDE.md`, `02_GETTING_STARTED.md`

**완료 기준:** `evaluation_session`으로 5개 태스크 평가 + 대시보드에서 결과 확인

---

### Module 2 — Layer 1 기반 지표 6종 (4h)

**학습 목표:**
1. 6개 지표 각각의 공식과 적정 임계값을 설명할 수 있다
2. `add_evaluation()`, `detect_hallucination()` 등 직접 API를 호출할 수 있다
3. L1 Rule-based vs L3 LLM 환각 탐지 차이를 설명하고 선택 기준을 제시할 수 있다
4. 토큰 비율 분석으로 프롬프트 효율 문제를 진단할 수 있다

**시간 배분:**
- 2-1. TCR: 30분
- 2-2. Accuracy (가중 알고리즘 + 코드 AST): 45분
- 2-3. Hallucination (+ L1 vs L3 비교): 45분
- 2-4. Response Quality (5차원): 30분
- 2-5. Latency + Token Economy: 45분
- 2-6. Lab — evaluation_session + 복수 모니터: 45분

**참조 Docs:** `06_METRICS_GUIDE.md` (핵심), `14_API_REFERENCE.md`, `11_GOLDEN_DATASET_GUIDE.md`

**완료 기준:** 3가지 품질 tier(high/hallucination/low_quality) 분리 결과 확인

---

### Module 3 — Layer 2 에이전틱 + 보안 지표 (4h)

**학습 목표:**
1. Tool Selection F1 공식을 직접 계산할 수 있다
2. 3가지 에이전트 협업 패턴(Hub/Chain/Mesh)을 식별할 수 있다
3. 5가지 보안 위협을 탐지하고 보안 지표를 해석할 수 있다
4. Known Issues(overall_score=0, API 변경)를 인지하고 올바른 코드를 작성할 수 있다

**시간 배분:**
- 3-1. 에이전틱 개요: 15분
- 3-2. Tool Call + Tool Selection F1: 45분
- 3-3. Retry & Correction: 30분
- 3-4. Coordination + Workflow: 45분
- 3-5. 보안 지표 5종 완전 분석: 75분 ← 핵심

**참조 Docs:** `07_AGENTIC_AI_METRICS_GUIDE.md`, `08_SECURITY_METRICS_GUIDE.md`, `16_KNOWN_ISSUES_AND_QUIRKS.md` (신규)

**완료 기준:** 04_security_eval.py 실행 + 보안 탭 L1/L2 점수 해석

---

### Module 4 — Layer 3 하이브리드 평가 (3h)

**학습 목표:**
1. Rule-based 평가의 한계를 예시로 설명할 수 있다
2. DeepEval 5개 지표를 실제 API로 호출할 수 있다
3. 좋은 G-Eval criteria를 직접 작성할 수 있다
4. Ragas 4개 지표에서 RAG 개선 방향을 도출할 수 있다
5. 비용×정밀도 매트릭스로 레이어 조합을 결정할 수 있다

**시간 배분:**
- 4-1. LLM 평가 필요성: 20분
- 4-2. DeepEval 5개 지표 + G-Eval 작성: 45분
- 4-3. Ragas 4개 지표 + RAG 개선 사이클: 45분
- 4-4. 대시보드 RAG/DeepEval 탭: 30분
- 4-5. 레이어 선택 매트릭스: 20분

**참조 Docs:** `10_KOREAN_RAG_GUIDE.md` (핵심), `06_METRICS_GUIDE.md`, `16_KNOWN_ISSUES_AND_QUIRKS.md`

**사전 요구사항:** `OPENAI_API_KEY` 설정 필수

**완료 기준:** 05_hybrid_eval.py 실행 + RAG/DeepEval 탭 지표 해석

---

### Module 5 — 프레임워크 통합 + 실무 파이프라인 (3h)

**학습 목표:**
1. 4개 프레임워크의 통합 패턴 차이를 설명할 수 있다
2. 크로스 프레임워크 파이프라인에서 핸드오프를 추적할 수 있다
3. 환경별(dev/staging/prod) 품질 게이트를 설계할 수 있다
4. GitHub Actions에 평가 파이프라인을 통합할 수 있다

**시간 배분:**
- 5-1. 4개 프레임워크 통합 전략: 60분
- 5-2. 크로스 프레임워크 분석 (10_cross_framework_eval.py): 45분
- 5-3. 품질 게이트 + CI/CD: 45분
- 5-4. Lab — 나만의 파이프라인 설계: 30분

**참조 Docs:** `09_FRAMEWORK_INTEGRATION.md` (핵심), `12_THRESHOLD_CONFIGURATION_GUIDE.md`, `13_DEPLOYMENT_GUIDE.md`, `FRAMEWORK_METRICS_MAP.md`

**완료 기준:** 자신의 에이전트 적용 가능한 품질 게이트 설계서 작성
