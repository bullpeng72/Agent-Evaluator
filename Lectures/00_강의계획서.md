## 사전 준비 사항

### 환경 설치

```bash
# 1. 저장소 클론
git clone [repo] && cd Agent-Evaluator

# 2. 기본 설치 (Module 1–4)
pip install -e ".[llm,serve]"

# 3. Layer 3 포함 (Module 4)
pip install -e ".[all]"

# 4. .env 파일 설정
cp Evaluator_Examples/.env.example Evaluator_Examples/.env
# → Evaluator_Examples/.env 에 API 키 입력

# 5. 설치 확인
agent-eval check

# 6. 대시보드 테스트
agent-eval dashboard --port 8765
```

### `.env` 필드 설명

```bash
# Module 1–3: API 키 없이 동작 (Layer 1/2 네이티브)
OPENAI_API_KEY=sk-...          # M2 LLM Judge 실습 / M4 (Layer 3) 필수
ANTHROPIC_API_KEY=sk-ant-...   # M2 LLM Judge (Claude 사용 시) / ClaudeHelper
LANGCHAIN_TRACING_V2=false     # Ragas 사용 시 false 권장
AGENT_EVALUATOR_OUTPUT_DIR=./results
OPENAI_MODEL=gpt-4o-mini       # LLM Judge 기본 모델 (agent-eval init으로 설정)
ANTHROPIC_MODEL=claude-haiku-4-5-20251001  # LLM Judge Claude 모델
```

## 모듈별 강의 계획 상세

### Module 1 — 에이전트 평가의 필요성과 SDK 전체 구조 (2h)

**학습 목표:**
1. 전통 소프트웨어 테스트와 AI 에이전트 평가의 차이를 설명할 수 있다
2. 3-Layer 구조와 16개 트래커의 역할을 파악할 수 있다
3. `PerformanceMonitor`와 `TaskResult`를 직접 코딩할 수 있다
4. 대시보드를 실행하고 6개 탭의 목적을 이해할 수 있다

**시간 배분:**
- 1-1. 왜 어려운가 + 실패 유형 4가지: 30분
- 1-2. 아키텍처 + TaskResult + create_taskresult: 45분
- 1-3. 환경 설정 + 대시보드 첫 실행: 45분

**참조 Docs:** `01_QUICK_START.md`, `08_DASHBOARD_GUIDE.md`

**완료 기준:** `evaluation_session`으로 5개 태스크 평가 + 대시보드에서 결과 확인

---

### Module 2 — Layer 1 기반 지표 6종 + LLM Judge (4h)

**학습 목표:**
1. 6개 지표 각각의 공식과 적정 임계값을 설명할 수 있다
2. `add_evaluation()`, `detect_hallucination()` 등 직접 API를 호출할 수 있다
3. L1 Rule-based vs L3 LLM 환각 탐지 차이를 설명하고 선택 기준을 제시할 수 있다
4. 토큰 비율 분석으로 프롬프트 효율 문제를 진단할 수 있다
5. `LLMJudge`로 `ground_truth` 없이 completeness·relevance·factual_consistency 3차원을 자동 채점할 수 있다

**시간 배분:**
- 2-1. TCR: 30분
- 2-2. Accuracy (가중 알고리즘 + 코드 AST): 45분
- 2-3. Hallucination (+ L1 vs L3 비교): 45분
- 2-4. Response Quality (5차원): 30분
- 2-5. Latency + Token Economy: 45분
- 2-6. **LLM Judge** — ground_truth 없는 오픈도메인 채점, sample_rate·비용 제어: 30분
- 2-7. Lab — evaluation_session + 복수 모니터: 15분

**참조 Docs:** `02_METRICS_REFERENCE.md` (핵심), `07_API_REFERENCE.md`, `04_GOLDEN_DATASET_GUIDE.md`

**사전 요구사항:** LLM Judge 실습 시 `OPENAI_API_KEY` 또는 `ANTHROPIC_API_KEY` 중 하나 필요

**완료 기준:** 3가지 품질 tier(high/hallucination/low_quality) 분리 결과 확인 + LLM Judge 3개 차원 점수 출력

---

### Module 3 — Layer 2 에이전틱 + 보안 지표 + 멀티턴 대화 평가 (4h)

**학습 목표:**
1. Tool Selection F1 공식을 직접 계산할 수 있다
2. 3가지 에이전트 협업 패턴(Hub/Chain/Mesh)을 식별할 수 있다
3. 5가지 보안 위협을 탐지하고 보안 지표를 해석할 수 있다
4. `ConversationSession`으로 맥락 유지율·주제 일관성·점진적 심화 지표를 측정할 수 있다

**시간 배분:**
- 3-1. 에이전틱 개요: 15분
- 3-2. Tool Call + Tool Selection F1: 45분
- 3-3. Retry & Correction: 30분
- 3-4. Coordination + Workflow: 45분
- 3-5. 보안 지표 5종 완전 분석: 60분 ← 핵심
- 3-6. **멀티턴 대화 평가** — ConversationSession, ConversationMetrics 5개 지표: 25분

**참조 Docs:** `02_METRICS_REFERENCE.md` (핵심), `07_API_REFERENCE.md`

**완료 기준:** 04_security_eval.py + 03_agentic_eval.py 실행 + 보안 탭 L1/L2 + ConversationSession 지표 5종 해석

---

### Module 4 — Layer 3 하이브리드 평가 (3h)

**학습 목표:**
1. Rule-based 평가의 한계를 예시로 설명할 수 있다
2. DeepEval 5개 지표를 실제 API로 호출할 수 있다
3. 좋은 G-Eval criteria를 직접 작성할 수 있다
4. Ragas 4개 지표에서 RAG 개선 방향을 도출할 수 있다
5. 비용×정밀도 매트릭스로 레이어 조합을 결정할 수 있다

**시간 배분:**
- 4-1. LLM 평가 필요성: 20분
- 4-2. DeepEval 5개 지표 + G-Eval 작성: 45분
- 4-3. Ragas 4개 지표 + RAG 개선 사이클: 45분
- 4-4. 대시보드 RAG/DeepEval 탭: 30분
- 4-5. 레이어 선택 매트릭스: 20분

**참조 Docs:** `10_KOREAN_RAG_GUIDE.md` (핵심), `02_METRICS_REFERENCE.md`

**사전 요구사항:** `OPENAI_API_KEY` 설정 필수

**완료 기준:** 05_hybrid_eval.py 실행 + RAG/DeepEval 탭 지표 해석

---

### Module 5 — 프레임워크 통합 + CI/CD 품질 게이트 + 실시간 모니터링 (4h)

**학습 목표:**
1. 4개 프레임워크의 통합 패턴 차이를 설명할 수 있다
2. 크로스 프레임워크 파이프라인에서 핸드오프를 추적할 수 있다
3. 환경별(dev/staging/prod) 품질 게이트를 설계할 수 있다
4. `agent-eval gate`로 임계값 기반 CI 자동 통과/실패를 구현할 수 있다
5. GitHub Actions 워크플로우에 `agent-eval gate`를 통합할 수 있다
6. `agent-eval monitor`로 Phoenix + OTEL 실시간 운영 모니터링을 활성화할 수 있다 (v0.7.0)

**시간 배분:**
- 5-1. 4개 프레임워크 통합 전략: 60분
- 5-2. 크로스 프레임워크 분석 (10_cross_framework_eval.py): 45분
- 5-3. **`agent-eval gate` CLI** — 임계값 설정, 기준선 관리, 회귀 감지, JUnit XML: 45분
- 5-4. GitHub Actions 통합 실습: 30분
- 5-5. Lab — 나만의 파이프라인 + 게이트 설계: 30분 (증가)

**`agent-eval gate` 핵심 패턴:**
```bash
# 1. 기준선 저장 (최초 1회)
agent-eval gate results/baseline.json --save-baseline results/gate_baseline.json

# 2. CI에서 품질 게이팅
agent-eval gate results/ci_run.json \
  --tcr 85 --accuracy 70 --p95-latency 3.0 \
  --fail-on-regression 10 \
  --junit-xml results/gate_report.xml
# 종료 코드: 0=통과 / 1=임계값 미달 / 2=회귀 감지
```

**참조 Docs:** `03_FRAMEWORK_GUIDE.md` (핵심), `05_THRESHOLD_GUIDE.md`, `06_DEPLOYMENT_GUIDE.md`, `11_FRAMEWORK_COMPARISON.md`, `12_MONITOR_GUIDE.md`

**완료 기준:** 자신의 에이전트에 `agent-eval gate` 통합 + GitHub Actions YAML 초안 작성

1. 실제 또는 모의 에이전트에 대해 Layer 1/2 전수 평가 실행
2. 대시보드에서 5개 탭의 주요 지표 해석 보고서 작성

4. (권장) GitHub Actions 워크플로우 파일 작성 — `agent-eval gate` 통합
5. (선택) `LLMJudge` 또는 `ConversationSession` 중 하나를 실제 에이전트에 적용
