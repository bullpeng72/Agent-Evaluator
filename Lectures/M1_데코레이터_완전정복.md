### 핵심 코드 예제

#### 예제 1 — `@agent_eval` 기본 패턴

```python
# 출처: Evaluator_Examples/04_decorator_quickeval.py, 섹션 1
from agent_evaluator import PerformanceMonitor
from agent_evaluator.decorators import agent_eval

monitor = PerformanceMonitor(output_dir="results/")

# question/ground_truth 파라미터 이름 자동 탐지
@agent_eval(monitor, task_type="qa", task_id_prefix="basic")
def basic_agent(question: str, ground_truth: str = "") -> str:
    return f"답변: {question}"

# 파라미터 이름이 다를 때 명시적 지정
@agent_eval(monitor, task_type="qa",
            question_arg="query", ground_truth_arg="expected",
            task_id_prefix="param")
def custom_param_agent(query: str, expected: str = "") -> str:
    return f"응답: {query}"

basic_agent("대한민국의 수도는?", ground_truth="서울")
custom_param_agent(query="파이썬의 창시자는?", expected="귀도 반 로섬")
```

- `@agent_eval(monitor, task_type="qa")` 데코레이터 하나로 AccuracyEvaluator·LatencyTracker·TCR이 모두 자동 활성화된다
- `question`, `ground_truth` 파라미터 이름을 자동으로 탐지하므로 별도 설정 없이 동작한다
- `question_arg`/`ground_truth_arg`로 다른 이름의 파라미터도 지정할 수 있다

#### 예제 2 — `EvalMetadata` 튜플 반환

```python
# 출처: Evaluator_Examples/04_decorator_quickeval.py, 섹션 3
from agent_evaluator.decorators import agent_eval, EvalMetadata

@agent_eval(
    monitor, task_type="tool_use",
    score_fn=lambda r, gt: 0.1,   # EvalMetadata에 의해 무시됨
    task_id_prefix="meta",
)
def meta_agent(question: str, ground_truth: str = "") -> tuple:
    response = f"도구 실행 결과: {question}"
    return response, EvalMetadata(
        accuracy_score=0.92,          # score_fn(0.1)보다 우선
        attempts=3,
        framework="langchain",
        expected_tools=["search", "calculator"],
        tool_calls=[
            {"tool_name": "search",     "success": True,  "duration": 0.5},
            {"tool_name": "calculator", "success": True,  "duration": 0.1},
        ],
    )

meta_agent("검색 후 계산해줘", ground_truth="계산 완료")
```

- 함수가 `(response, EvalMetadata(...))` 튜플을 반환하면 데코레이터가 자동으로 분리한다
- **우선순위**: EvalMetadata > score_fn > 자동 계산. EvalMetadata(accuracy_score=0.92)가 있으면 score_fn의 0.1은 무시된다
- `tool_calls`, `expected_tools`, `framework` 필드로 Layer 2 트래커(ToolCallAnalyzer, ToolSelectionTracker)에 데이터를 직접 주입한다

#### 예제 3 — `QuickEval` Facade

```python
# 출처: Evaluator_Examples/04_decorator_quickeval.py, 섹션 8
from agent_evaluator import QuickEval

eval_qe = QuickEval(
    output_dir="results/",
    auto_save=True,

@eval_qe.qa
def qe_qa_agent(question: str, ground_truth: str = "") -> str:
    return f"답변: {question}"

@eval_qe.rag
def qe_rag_agent(question: str, context: str = "", ground_truth: str = "") -> str:
    return context[:80] if context else "컨텍스트 없음"

qe_qa_agent("한국의 국화는?", ground_truth="무궁화")
qe_rag_agent("서울의 특징은?", context="서울은 대한민국의 수도입니다.", ground_truth="수도")

# CI/CD 게이팅 (실패 시 sys.exit(1))

    eval_qe.gate(tcr=50, accuracy=30)
    print("gate() 통과")
```

- `gate(tcr=50, accuracy=30)`이 기준 미달이면 `sys.exit(1)`을 호출해 CI 파이프라인을 중단시킨다

## 1. 왜 데코레이터인가?

### 1.1 데코레이터 이전의 세계

SDK가 데코레이터를 제공하기 전, 에이전트 함수 하나를 평가하려면 다음과 같은 보일러플레이트 코드가 필요했다.

```python
import time
from agent_evaluator import PerformanceMonitor, TaskResult, TaskType

monitor = PerformanceMonitor("results/")

def my_agent(question: str) -> str:
    return llm.invoke(question)

# 직접 TaskResult 구성 — 11개 필수 필드를 모두 채워야 함
def run_and_evaluate(question: str, ground_truth: str) -> str:
    start = time.time()
    success = True
    response = ""
    errors = []

    try:
        response = my_agent(question)
    except Exception as e:
        success = False
        errors.append(str(e))

    elapsed = time.time() - start

    result = TaskResult(
        task_id=f"task_{int(time.time())}",   # 직접 생성
        task_type=TaskType.QA,                 # Enum 직접 지정
        success=success,
        completion_score=1.0 if success else 0.0,
        accuracy_score=0.0,                    # 직접 계산 필요
        execution_time=elapsed,
        tokens_used=0,                         # 직접 추출 필요
        tool_calls=[],
        attempts=1,
        errors=errors,
        timestamp=datetime.utcnow(),           # 직접 생성
    )

    monitor.record_task(result)
    return response
```

이 코드의 문제점:
- **11개 필수 필드**를 항상 직접 채워야 한다
- `execution_time` 측정을 잊으면 데이터가 0이 된다
- `accuracy_score` 계산 로직을 별도로 구현해야 한다
- 예외 처리를 잊으면 `completion_score`가 잘못 기록된다
- 에이전트 함수마다 이 코드를 반복해야 한다

### 1.2 데코레이터 이후의 세계

```python
from agent_evaluator import agent_eval, PerformanceMonitor

monitor = PerformanceMonitor("results/")

@agent_eval(monitor, task_type="qa")  # ← 핵심 데코레이터 직접 사용
def my_agent(question: str, ground_truth: str = "") -> str:
    return llm.invoke(question)
```

데코레이터가 자동으로 처리하는 것들:
- `execution_time` 측정 (나노초 단위)
- `success` / `completion_score` 결정 (task_type 인식 — `code_generation`은 AST, `tool_use`는 tool_calls 여부, 기타는 길이 기반)
- `accuracy_score` 계산 (4-way weighted scoring)
- `task_id` 자동 생성
- `tokens_used` 자동 추출 (framework adapter 사용)
- `monitor.record_task()` 자동 호출

SDK의 **표준 인터페이스**는 용도에 따라 통합된 3개의 데코레이터다:

| 데코레이터 | 대상 | 주요 결과 |
|---|---|---|
| **`@agent_eval`** | 단일 호출 (Single-turn) | `TaskResult` 1개 |
| **`@batch_eval`** | 대량 데이터 (Batch) | `TaskResult` N개 |
| **`@conversation_eval`** | 멀티턴 대화 (Multi-turn) | `ConversationMetrics` 1개 |

> **Note**: `QuickEval`이나 `EvalDecorator`는 위 데코레이터들을 편리하게 생성해주는 **팩토리(Factory)** 객체일 뿐이며, 모든 핵심 로직은 위 3개 데코레이터에 집약되어 있다.

### 1.3 어떤 데코레이터를 써야 하는가? — 빠른 선택 가이드

| 나의 상황 | 사용 데코레이터 | 핵심 이유 |
|----------|--------------|---------|
| 에이전트 함수 1개, 질문 1건씩 처리 | `@agent_eval` | 가장 기본. 단일 호출 1건 = TaskResult 1개 |
| 이미 질문 목록(list)이 있고 한꺼번에 평가 | `@batch_eval` | 루프 없이 배치 전체 처리 + DataFrame 반환 가능 |
| 챗봇 / 멀티턴 대화를 평가 | `@conversation_eval` | 세션 맥락 유지율, 주제 일관성 등 대화 전용 지표 |
| 외부 라이브러리 콜백이라 함수에 데코레이터 못 붙임 | `eval_context` with 블록 | 데코레이터 패턴 불가능한 상황의 탈출구 |
| 여러 에이전트에 동일 설정(framework, alert 등) 반복 적용 | `EvalDecorator` | 공통 설정 1회 정의 → 모든 에이전트에 자동 전파 |
| 처음 시작 / 최소 코드로 빠르게 테스트 | `QuickEval` | 1줄로 시작, 단축 속성 `.qa` `.rag` `.tool_use` 등 제공 |

**에이전트 유형별 추천 조합:**

```
QA 봇 (단일 질문-답변)
    → @eval.qa  또는  @agent_eval(monitor, task_type="qa")

RAG 에이전트 (문서 기반 검색+생성)
    → @eval.rag  또는  @agent_eval(monitor, task_type="information_retrieval", rag_mode=True)

도구 호출 에이전트 (LangChain/OpenAI tools)
    → @agent_eval(monitor, task_type="tool_use", framework="langchain")

멀티에이전트 오케스트레이션
    → @agent_eval(monitor, task_type="tool_use", framework="crewai")  또는  framework="autogen"

챗봇 / 고객 상담 에이전트
    → @conversation_eval(monitor, session_id_arg="sid", max_turns=20)

코드 생성 에이전트
    → @agent_eval(monitor, task_type="code_generation")

퍼블릭 서비스 (보안이 중요)
    → @agent_eval(monitor, task_type="qa", security=SecurityConfig())
    → 또는 PerformanceMonitor(enable_security_metrics=True)
```

### 1.4 아키텍처 관계도 — 데코레이터와 레이어의 연결

데코레이터는 **생산자(Producer)**, Layer 트래커들은 **소비자(Consumer)**, 둘을 연결하는 **계약 지점**은 `PerformanceMonitor.record_task()`다.

```
┌──────────────────────────────────────────────────────────────┐
│                   데코레이터 레이어 (생산자)                   │
│  @agent_eval  @batch_eval  @conversation_eval  eval_context  │
│               QuickEval · EvalDecorator (팩토리)              │
└─────────────────────────┬────────────────────────────────────┘
                          │  ① 함수 실행 + execution_time 자동 측정
                          │  ② framework 어댑터로 tokens/tool_calls 추출
                          │  ③ EvalMetadata 병합
                          │  ④ TaskResult 자동 생성
                          ▼
┌────────────────────────────────────────────────────────────┐
│     PerformanceMonitor.record_task(task)  ← 계약 지점      │
│           모든 활성 트래커에 TaskResult 분배               │
└──────┬──────────┬──────────┬──────────┬──────────┬─────────┘
       │          │          │          │          │
       ▼          ▼          ▼          ▼          ▼
   [L1 항상]  [L1 항상]  [L2 자동]  [L2 자동]  [L2 opt-in]
   TCR        Accuracy   ToolCall   Workflow   Security
   Latency    Quality    Retry      Coord.     (5종)
   Token      Halluc.*   Selection
```

> `*` Hallucination은 `rag_mode=True` 또는 `enable_hallucination_detection=True` 필요.  
> L2 Agentic은 `tool_calls`·`chain_steps`·`agent_interactions` 데이터가 공급될 때 자동 활성.

**데코레이터가 자동으로 채우는 TaskResult 필드:**

| TaskResult 필드 | 데코레이터 자동 처리 방법 | 소비 트래커 |
|----------------|------------------------|------------|
| `execution_time` | `time.perf_counter()` 측정 | LatencyTracker |
| `success` / `completion_score` | task_type 인식 자동 계산 (`code_generation`→AST, `tool_use`→도구 여부, 기타→길이 기반) | TaskCompletionTracker |
| `accuracy_score` | `ground_truth` vs 반환값 4-way 계산 | AccuracyEvaluator |
| `tokens_used` | `framework=` 어댑터 또는 `EvalMetadata` | TokenEconomyTracker |
| `tool_calls` | `framework=` 어댑터 또는 `EvalMetadata` | ToolCallAnalyzer, ToolSelectionTracker |
| `extra.chain_steps` | `framework=` 어댑터 자동 추출 | WorkflowExecutionTracker |
| `extra.agent_interactions` | `EvalMetadata` 수동 주입 | AgentCoordinationTracker |
| `attempts` / `errors` | `EvalMetadata` 또는 자동 카운트 | RetryCorrectionTracker |
| `question` / `response` | 함수 파라미터 `question=` 자동 매핑 | ResponseQualityEvaluator, HallucinationDetector |

## 2. @agent_eval 완전 해부

`@agent_eval`은 `agent_evaluator.core`의 트래커들을 통합 제어하는 싱글턴 에이전트용 인터페이스다.

### 2.1 기본 구조

```python
@agent_eval(
    monitor,                    # 필수: 결과를 기록할 모니터
    task_type="qa",             # 필수: 태스크 유형
    framework="openai",         # 선택: 자동 메타데이터 추출
    rag_mode=False,             # 선택: RAG 모드 활성
)
def my_agent(question: str, ground_truth: str = "") -> str:
    return llm.invoke(question)
```

함수 시그니처 규칙:
- 첫 번째 위치 인자(여기서는 `question`)가 평가할 질문으로 자동 인식된다
- `ground_truth_arg`로 지정한 이름의 파라미터(여기서는 `expected`)가 정답으로 사용된다
- 기본값이 `ground_truth_arg`이므로, `ground_truth=""` 라고 파라미터를 명명하면 별도 지정 없이 자동 인식된다

### 2.2 task_type 파라미터

`task_type`은 평가 방식과 지표 해석에 영향을 준다. 지원하는 값:

| task_type | 설명 | 주요 지표 |
|---|---|---|
| `"qa"` | 질의응답 | Accuracy (4-way), TCR |
| `"tool_use"` | 도구 호출 에이전트 | Tool Call Analyzer, Tool Selection F1 |
| `"information_retrieval"` | RAG / 검색 | Hallucination (context 필요) |
| `"code_generation"` | 코드 생성 | AST 비교 기반 Accuracy |
| `"reasoning"` | 추론 태스크 | Multi-step chain analysis |
| `"creative"` | 창의적 생성 | Quality 5차원 |
| `"planning"` | 계획 수립 | Workflow Execution |
| `"data_analysis"` | 데이터 분석 | Accuracy + Quality |
| `"tool_use"` | 멀티에이전트 / 도구 호출 | Coordination Tracker, Tool Selection F1 |

```python
# 코드 생성 평가 — AST 비교 자동 활성화
@agent_eval(monitor, task_type="code_generation")
def code_agent(question: str, ground_truth: str = "") -> str:
    return llm.invoke(f"Write Python code for: {question}")

# 도구 호출 평가 — Tool Selection F1 자동 계산
@agent_eval(
    monitor,
    task_type="tool_use",
    expected_tools_arg="expected_tools",  # 어떤 도구를 써야 하는지 인자
)
def tool_agent(question: str, ground_truth: str = "", expected_tools: list = None) -> str:
    return agent_executor.invoke({"input": question})
```

### 2.3 framework 파라미터 — 21개 프레임워크 지원

`framework` 파라미터를 지정하면 해당 프레임워크의 응답 객체에서 메타데이터를 자동 추출한다.

```python
# 지원 프레임워크 목록
SUPPORTED_FRAMEWORKS = [
    "langchain", "langgraph", "crewai", "autogen",
    "dspy", "pydanticai",
    "anthropic", "openai", "gemini", "llamaindex", "haystack",
    "vertexai", "ollama", "cohere", "groq", "mistral", "bedrock",
    "smolagents", "semantic_kernel", "vllm", "huggingface",
]
```

각 프레임워크별 자동 추출 정보:

| 프레임워크 | 추출 항목 |
|---|---|
| `langchain` | `usage_metadata`, `tool_calls` (AIMessage), chain_steps |
| `openai` | `usage.total_tokens`, `choices[0].message.tool_calls` |
| `anthropic` | `usage.input_tokens`, `content[].tool_use`, 캐시 토큰 |
| `gemini` | `usage_metadata`, `candidates[0].content.parts[].function_call` |
| `crewai` | `token_usage`, `output_pydantic` |

```python
# OpenAI 프레임워크 지정
@agent_eval(monitor, task_type="qa", framework="openai")
def openai_agent(question: str, ground_truth: str = "") -> str:
    response = client.chat.completions.create(
        model="gpt-4o-mini",
        messages=[{"role": "user", "content": question}]
    )
    return response  # 객체 전체를 반환 — 데코레이터가 메타데이터 추출

# Anthropic 프레임워크 지정
@agent_eval(monitor, task_type="qa", framework="anthropic")
def claude_agent(question: str, ground_truth: str = "") -> str:
    response = anthropic_client.messages.create(
        model="claude-sonnet-4-6",
        max_tokens=1024,
        messages=[{"role": "user", "content": question}]
    )
    return response  # 응답 객체 전체 반환
```

> **중요**: `framework`를 지정할 때 함수가 문자열이 아닌 SDK 응답 **객체 전체**를 반환해야 한다.
> 데코레이터가 객체에서 텍스트와 메타데이터를 동시에 추출한다.

#### auto_detect_framework

`auto_detect_framework=True`(기본값)이면 framework를 명시하지 않아도 응답 객체의 속성을 보고 프레임워크를 자동 감지한다.

```python
# framework= 생략 가능 — 응답 타입을 보고 자동 감지
@agent_eval(monitor, task_type="qa")  # auto_detect_framework=True 기본
def smart_agent(question: str, ground_truth: str = "") -> str:
    return any_llm_sdk_call(question)
```

감지 기준 (12개 속성 기반):
- `response.model` + `response.content` → anthropic
- `response.choices` + `response.usage` → openai
- `response.candidates` → gemini
- `response._completions` → dspy
- `response.all_messages()` → pydanticai

### 2.6 enable_* 파라미터 시리즈

개별 기능을 이번 호출에만 임시 활성화/비활성화.

```python
from agent_evaluator import LLMJudgeConfig

@agent_eval(
    monitor,
    task_type="qa",
    enable_hallucination_detection=True,  # 환각 탐지 임시 활성

    return llm.invoke(question)
```

LLM Judge가 평가하는 기본 5차원:
- **completeness**: 질문의 모든 측면을 다루었는가
- **relevance**: 질문에 관련된 답변인가
- **factual_consistency**: 사실과 일치하는가
- **toxicity**: 독성 콘텐츠 포함 여부 (낮을수록 좋음)
- **bias**: 편향 콘텐츠 포함 여부 (낮을수록 좋음)

v0.7.6부터 두 가지 확장 차원이 추가되었다:
- **faithfulness** (조건부): `rag_mode=True + llm_judge=LLMJudgeConfig()` 조합 시 context가 있으면 자동 추가. Ragas LLM-based Faithfulness 대체.
- **커스텀 기준** (`criteria`): 서비스 특화 평가 기준을 직접 정의. DeepEval G-Eval 대체.

```python
)
```

### 2.7 재시도(Retry) 파라미터

에이전트 호출 실패 시 자동 재시도. Exponential backoff 내장.

```python
from agent_evaluator import RetryConfig

@agent_eval(
    monitor,
    task_type="qa",
    retry=RetryConfig(max=3, delay=1.0, backoff=2.0),  # 최대 3회 재시도, 1초→2초→4초 대기
)
def flaky_agent(question: str, ground_truth: str = "") -> str:
    # 가끔 실패하는 외부 API 호출
    return unstable_api.call(question)
```

재시도 로직:
1. 1차 시도 → 실패
2. 1.0초 대기 → 2차 시도 → 실패
3. 2.0초 대기 → 3차 시도 → 실패
4. 4.0초 대기 → 4차 시도 → 실패 시 `attempts=4`, `errors=[...]` 기록

`retry=RetryConfig` 고급 옵션도 있다:

```python
from agent_evaluator.decorators import agent_eval, RetryConfig

@agent_eval(
    monitor,
    task_type="qa",
    retry=RetryConfig(max=3, jitter_type="full", max_delay=30.0,
                     should_retry=lambda e: isinstance(e, RateLimitError)),
    alert_rules=[alert_rule],
)
def agent(question: str, ground_truth: str = "") -> str:
    return llm.invoke(question)
```

### 2.9 score_fn 파라미터 — 커스텀 정확도 함수

기본 4-way 정확도 계산 대신 사용자 정의 채점 함수를 사용한다.

```python
# 커스텀 정확도 함수: (response, ground_truth) → float (0.0 ~ 1.0)
def my_accuracy(response: str, ground_truth: str) -> float:
    # 예: 특정 키워드 포함 여부
    keywords = ground_truth.lower().split()
    hits = sum(1 for kw in keywords if kw in response.lower())
    return hits / len(keywords) if keywords else 0.0

@agent_eval(
    monitor,
    task_type="qa",
    score_fn=my_accuracy,       # 커스텀 함수 적용
)
def agent(question: str, ground_truth: str = "") -> str:
    return llm.invoke(question)
```

도메인 특화 평가에 유용하다:
- 의료: ICD 코드 매칭
- 법률: 법령 조항 정확도
- 수학: 수식 동치 검증

### 2.18 EvalMetadata를 통한 인라인 메타데이터

함수 내부에서 추가 메타데이터를 주입하려면 `(response, EvalMetadata(...))` 튜플을 반환한다.

```python
from agent_evaluator import EvalMetadata

@agent_eval(monitor, task_type="tool_use", framework="langchain")
def agent(question: str, ground_truth: str = "") -> tuple:
    result = agent_executor.invoke({"input": question})
    response_text = result["output"]
    
    # 추가 메타데이터 수동 주입
    metadata = EvalMetadata(
        accuracy_score=0.95,                    # 직접 계산한 정확도
        tool_calls=result.get("intermediate_steps", []),
        tokens_used=result.get("token_usage", {}).get("total", 0),
        chain_steps=[step[0].tool for step in result.get("intermediate_steps", [])],
        agent_interactions=[],                  # 멀티에이전트 교환 기록
    )
    return response_text, metadata  # ← 튜플 반환 시 EvalMetadata 자동 처리
```

| `tool_calls` | list | 도구 호출 기록 |
| `tokens_used` | int | 사용된 토큰 수 |
| `chain_steps` | list | 체인 실행 단계 |

## 3. @batch_eval 완전 해부

### 3.1 기본 개념

`@batch_eval`은 질문 목록을 받아 모든 질문을 평가하고 결과를 반환한다.

```python
from agent_evaluator import batch_eval, PerformanceMonitor

monitor = PerformanceMonitor("results/")

@batch_eval(monitor, task_type="qa")
def batch_agent(questions: list, ground_truths: list = None) -> list:
    # questions 목록의 각 항목에 대해 응답 생성
    return [llm.invoke(q) for q in questions]

# 호출
```

### 3.3 concurrent 파라미터 — 병렬 처리

```python
@batch_eval(
    monitor,
    task_type="qa",
    concurrent=True,        # asyncio.gather로 병렬 실행
    max_concurrent=10,      # 최대 동시 실행 수 (기본: 10)
)
async def concurrent_batch(questions: list, ground_truths: list = None) -> list:
    # 내부에서 gather로 병렬 실행되므로 async 함수여야 함
    tasks = [async_llm.ainvoke(q) for q in questions]
    return await asyncio.gather(*tasks)

# 100개 질문을 10개씩 병렬로 처리 → 대략 10배 속도 향상
responses = await concurrent_batch(questions * 10, ground_truths * 10)
```

```python
@batch_eval(
    monitor,
    task_type="qa",
    shuffle=True,                   # 처리 전 질문 순서 무작위 섞기
    item_timeout=30.0,              # 항목당 최대 처리 시간 (초)
    on_batch_progress=lambda i, n, tr: print(f"{i}/{n} 완료"),  # 진행상황 콜백
    on_item_error=lambda e, q: print(f"오류: {q} → {e}"),       # 항목 오류 콜백
    streaming_mode=True,            # 메모리 효율적 스트리밍 처리
    flush_every=50,                 # 50건마다 자동 저장
    allow_duplicate_task_ids=False, # task_id 중복 허용 여부
    strict_types=True,              # 타입 검증 강화
)
def batch_agent(questions: list, ground_truths: list = None) -> list:
    return [llm.invoke(q) for q in questions]
```

`streaming_mode=True`는 대용량 배치(수천~수만 건)에서 전체 결과를 메모리에 올리지 않고 처리한다.

## 4. @conversation_eval 완전 해부

`ConversationSession`을 수동으로 관리하던 패턴이 데코레이터로 완전히 통합되었습니다. 현재는 `@conversation_eval` 데코레이터 사용을 권장하며, `ConversationSession` 직접 사용은 고급 시나리오에서만 필요합니다.

### 4.1 기본 개념

멀티턴 대화를 평가할 때 사용하며, `session_id`가 같은 호출들을 하나의 세션으로 묶어 맥락 유지율(Context Retention) 등을 계산합니다.

```python
from agent_evaluator import conversation_eval, flush_conversation, PerformanceMonitor

monitor = PerformanceMonitor("results/")

@conversation_eval(
    monitor, 
    session_id_arg="sid", 
    max_turns=10,
    on_flush=lambda metrics, sid: print(f"세션 {sid} 종료: {metrics.overall_score}")
)
def chat_agent(question: str, sid: str = "default") -> str:
    return chatbot.chat(question)

# 턴 누적 (자동)
chat_agent("안녕하세요!", sid="user_001")
chat_agent("오늘 날씨 어때요?", sid="user_001")

# 세션 명시적 종료 (지표 계산 및 기록)
flush_conversation("user_001")
```

### 4.2 세션 자동 종료

`max_turns`에 도달하면 자동으로 세션이 종료되고 메트릭이 계산된다.

```python
@conversation_eval(
    monitor,
    max_turns=5,            # 5턴 후 자동 종료
    max_turns_exceeded_action="flush",  # "flush" (기본) or "error" or "ignore"
)
def chat_agent(user_input: str, session_id: str = "default") -> str:
    return chatbot.chat(user_input)
```

### 4.3 on_turn 콜백

각 턴 완료 후 호출되는 콜백.

```python
def on_each_turn(turn_index: int, user_input: str, agent_response: str):
    print(f"턴 {turn_index}: [{user_input[:20]}] → [{agent_response[:20]}]")

@conversation_eval(
    monitor,
    max_turns=10,
    on_turn=on_each_turn,

    return chatbot.chat(user_input)
```

### 4.4 session_score_fn / turn_score_fn

세션 단위 및 턴 단위 커스텀 채점.

```python
def my_session_score(turns: list) -> float:
    """세션 전체의 품질 점수 계산"""
    if not turns:
        return 0.0
    # 첫 턴부터 마지막 턴까지 일관성 측정
    lengths = [len(t["response"]) for t in turns]
    return min(lengths) / max(lengths) if max(lengths) > 0 else 0.0

def my_turn_score(user_input: str, agent_response: str) -> float:
    """턴별 품질 점수"""
    # 응답이 질문에 키워드를 포함하는가
    question_words = set(user_input.split())
    response_words = set(agent_response.split())
    overlap = question_words & response_words
    return len(overlap) / len(question_words) if question_words else 0.0

@conversation_eval(
    monitor,
    max_turns=10,
    session_score_fn=my_session_score,
    turn_score_fn=my_turn_score,
)
def chat_agent(user_input: str, session_id: str = "default") -> str:
    return chatbot.chat(user_input)
```

### 4.5 기타 conversation_eval 파라미터

### 4.6 ConversationMetrics 해석

`flush_conversation()`이 반환하는 `ConversationMetrics` 객체의 주요 필드:

| 필드 | 범위 | 의미 |
|---|---|---|
| `turn_count` | int | 총 턴 수 |
| `overall_score` | 0.0~1.0 | 세션 종합 점수 |
| `context_retention` | 0.0~1.0 | 이전 대화 맥락 유지 능력 |
| `topic_coherence` | 0.0~1.0 | 주제 일관성 |

| `session_completion` | 0.0~1.0 | 세션 목표 달성도 |
| `avg_turn_latency` | float | 평균 응답 속도 (초) |
| `turn_scores` | dict | 턴별 품질 점수 `{0: 0.9, 1: 0.85, ...}` |

```python

    turn: score 
    for turn, score in (metrics.turn_scores or {}).items() 
    if score < 0.7

```

```python
)

# 오류 발생 알림
error_rule = AlertRuleBuilder.when_error(
    handler=lambda msg, tr: print(f"ERROR: {tr.errors}"),
    severity="critical",
)

# 도구 호출 과다 알림
tool_rule = AlertRuleBuilder.when_tool_calls_exceed(
    max_calls=10,
    handler=lambda msg, tr: log_warning(msg),
)
```

### 10.2 SimpleTaskAlertRule 고급 설정

```python
from agent_evaluator import SimpleTaskAlertRule

# 복합 조건
complex_rule = SimpleTaskAlertRule(
    name="high_risk_failure",
    condition=lambda tr: tr.accuracy_score < 0.5 and tr.execution_time > 3.0,
    handler=lambda msg, tr: escalate(msg, tr),
    severity="critical",
    cooldown=120,
    compound_conditions=[
        {"field": "tokens_used", "op": "gt", "value": 1000},
        {"field": "attempts", "op": "gt", "value": 1},
    ],
)

# dry_run — 핸들러 실행 없이 조건만 검사
result = complex_rule.dry_run(task_result)
print(f"조건 충족: {result}")  # True/False

# 클래스 레벨 쿨다운 (같은 이름의 모든 인스턴스 공유)
SimpleTaskAlertRule.class_level_cooldown["slow_response"] = 300
```

## 부록: 체크리스트

새 에이전트를 평가 설정할 때 다음 순서로 진행한다.

```
1. 에이전트 유형 결정
   □ 단일 질의 → @agent_eval
   □ 배치 처리 → @batch_eval  
   □ 대화형 → @conversation_eval

2. task_type 선택
   □ 일반 QA → "qa"
   □ 도구 사용 → "tool_use"
   □ RAG → "information_retrieval" + rag_mode=True
   □ 코드 생성 → "code_generation"

3. framework 지정
   □ 명시적 지정 → framework="openai"
   □ 자동 감지 → auto_detect_framework=True (기본)

4. 선택적 기능 활성화
   □ 환각 탐지 → enable_hallucination_detection=True
   □ 보안 검사 → security=SecurityConfig()
   □ LLM Judge → llm_judge=LLMJudgeConfig()

5. 운영 설정
   □ 알림 규칙 → alert_rules=[...]
   □ 자동 저장 → flush_every=50
   □ CI/CD 게이팅 → eval.gate(tcr=85) # (QuickEval 인스턴스 사용 시)

6. 결과 출력 시나리오 선택
   □ 터미널 즉시 확인 → monitor.generate_report().to_json(indent=2)
   □ 대시보드 → save_to_file("name") 후 agent-eval dashboard results/ --watch
   □ Phoenix OTEL → setup_otel() 먼저, 그다음 monitor 생성 → agent-eval monitor
```

## 12. 파라미터 × 지표 완전 매핑

데코레이터를 작성할 때 "이 파라미터가 어떤 지표를 수집하는가"를 한 곳에서 확인할 수 있는 종합 레퍼런스다.

### 12.1 지표 × 데코레이터 전체 매트릭스

```

──────────────────────  ───────────  ───────────  ──────────  ────────────────────────────
```

### 12.2 파라미터 → 지표 활성화 요약

| 파라미터 | 활성화 지표 | 조건 |
|---|---|---|
| `ground_truth_arg` | Accuracy | 인자 이름 일치 시 자동 |
| `rag_mode=True` | Hallucination Rate + context_arg 자동 설정 | context 인자 존재 시 |
| `context_arg` | Hallucination Rate | `enable_hallucination_detection=True` 동반 |
| `expected_tools_arg` | Tool Selection F1 | tool_calls 동시 필요 |
| `framework="langchain"` | Tool Call + Workflow Execution | LangChain 응답 객체 |
| `framework="crewai"` | Tool Call + Agent Coordination | CrewAI TaskOutput |
| `framework="autogen"` | Agent Coordination | AutoGen ChatResult |
| `framework="openai"` | Token Economy (정확) | OpenAI ChatCompletion |
| `security=SecurityConfig()` | 보안 5개 지표 전체 | 임시 활성 (finally 복원) |
| `allowed_tools=[...]` | Tool Authorization 화이트리스트 | security 동반 |
| `llm_judge=LLMJudgeConfig()` | LLMJudge 5차원 | `[llm]` extras |
| `rag_mode + llm_judge=LLMJudgeConfig()` | + Faithfulness | context 존재 시 |
| `llm_judge=LLMJudgeConfig(criteria=[...])` | + G-Eval 커스텀 기준 | |
| `retry=RetryConfig(max=N)` | Retry & Error Recovery | 실제 재시도 발생 시 |
| `score_fn` | Accuracy (커스텀) | `(response, gt) → float` |
| `completion_fn` | TCR (커스텀) | `(response, ...) → float` |
| `enable_anomaly_detection=True` | Anomaly Detection | save_to_file() 시 |

| `score_fn` | `None` | 커스텀 Accuracy 계산 |

| `dry_run` | `False` | 기록 없이 결과만 반환 |

### 12.4 실전 설정 예시

```python
from agent_evaluator import agent_eval, batch_eval, conversation_eval, PerformanceMonitor
from agent_evaluator import LLMJudgeConfig, SecurityConfig, RetryConfig

# ① 기본 QA — Layer 1 자동 수집

# → extra["llm_judge"]["faithfulness"] 자동 기록

# ⑦ G-Eval 커스텀 기준 (DeepEval 대체)
```
