## 5-1. 4개 프레임워크 통합 전략 (60분)

### 통합 방식 개요

Agent-Evaluator는 두 가지 방식으로 프레임워크와 통합된다:

```
방식 A: Factory 함수 (권장)
    원본 에이전트 → create_evaluated_*() → 평가가 주입된 에이전트
    → 코드 변경 최소화, 기존 에이전트 그대로 사용

방식 B: 수동 record_task()
    원본 에이전트 실행 → 결과 수집 → monitor.record_task()
    → 가장 범용적, 어떤 프레임워크에도 적용 가능
```

## 5-3. 품질 게이트 + CI/CD (45분)

### 품질 게이트 개념

프로덕션 배포 전에 에이전트가 최소 품질 기준을 통과하는지 자동으로 검증한다.

```
개발 → [Dev Gate] → 스테이징 → [Staging Gate] → 프로덕션
              ↓                         ↓
         빠른 피드백                종합 검증
         Layer 1만                  Layer 1+2 전체
         임계값 낮음                 임계값 높음
```

### 환경별 품질 게이트 설계

```python
from agent_evaluator import PerformanceMonitor

QUALITY_GATES = {
    "dev": {
        "task_completion_rate": 0.70,    # 개발 중 허용 낮음
        "avg_accuracy": 0.65,
        "hallucination_rate": 0.20,      # 10건 중 2건까지 허용
        "avg_latency_p95": 10.0,         # P95 10초
    },
    "staging": {
        "task_completion_rate": 0.85,
        "avg_accuracy": 0.80,
        "hallucination_rate": 0.10,
        "avg_latency_p95": 5.0,
        "tool_selection_f1": 0.75,       # Staging부터 Tool F1 체크
        "security_threat_rate": 0.05,    # 보안 위협 5% 이하
    },
    "production": {
        "task_completion_rate": 0.92,
        "avg_accuracy": 0.87,
        "hallucination_rate": 0.05,
        "avg_latency_p95": 3.0,
        "tool_selection_f1": 0.85,
        "security_threat_rate": 0.02,
        "token_efficiency": 0.8,
    }
}

def check_quality_gate(monitor: PerformanceMonitor, env: str) -> dict:
    """품질 게이트 검사"""
    gates = QUALITY_GATES[env]
    report = monitor.generate_report()
    results = {}
    passed = True

    for metric, threshold in gates.items():
        actual = report.get(metric, 0)
        ok = actual >= threshold

        results[metric] = {
            "threshold": threshold,
            "actual": actual,
            "passed": ok
        }

        if not ok:
            passed = False
            print(f"❌ {metric}: {actual:.3f} < {threshold} (임계값)")
        else:
            print(f"✅ {metric}: {actual:.3f} ≥ {threshold}")

    results["overall_passed"] = passed
    return results
```

### 실제 사용 패턴

```python

    exit(1)  # CI/CD 파이프라인 중단
else:
```

## 전체 과정 요약

### 5개 모듈 지식 맵

```
M1 — 기초
  └── 왜 에이전트 평가인가
  └── 3-Layer 아키텍처
  └── PerformanceMonitor + TaskResult

M2 — Layer 1 (기반 지표)
  └── TCR → 완료율
  └── Accuracy → 가중 알고리즘 (F1+Jaccard+LCS+Char)
  └── Hallucination → Rule-based vs L3 LLM 비교
  └── Quality → 5차원 레이더
  └── Latency → P50/P95/P99 퍼센타일
  └── Token Economy → I/O 비율 진단

M3 — Layer 2 (에이전틱 + 보안)
  └── Tool Call + Selection F1
  └── Retry → avg_retry_time 버그 (v0.6.0 수정)
  └── Coordination → overall_score 정상 계산 (v0.6.0에서 수정)
  └── Workflow → 퍼널 분석
  └── 보안 5종 → API 변경 이력 숙지 필수

M4 — Layer 3 (하이브리드)
  └── DeepEval → G-Eval criteria 작성법
  └── Ragas → 4지표 진단 매트릭스
  └── 레이어 선택 매트릭스
  └── Ragas 0.4.x API 변경

M5 — 통합 + 실무
  └── 4개 프레임워크 통합 패턴
  └── 크로스 프레임워크 핸드오프
  └── 품질 게이트 설계
  └── GitHub Actions CI/CD
```
