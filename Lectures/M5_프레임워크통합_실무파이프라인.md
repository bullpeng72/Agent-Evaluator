## 5-1. 4개 프레임워크 통합 전략 (60분)

### 통합 방식 개요

Agent-Evaluator는 세 가지 방식으로 프레임워크와 통합된다:

```
방식 A: @agent_eval(framework=...) 데코레이터 — 한 줄 적용 (권장)
    기존 함수 위에 데코레이터 한 줄 → 21개 프레임워크 응답 자동 파싱
    → 토큰·도구 추출 자동, 코드 변경 최소화

방식 B: 프레임워크 Factory 함수 — 기존 에이전트 객체 래핑
    원본 에이전트 → create_evaluated_*() → 평가가 주입된 에이전트
    → 기존 에이전트 그대로 사용, 객체 수준 통합

방식 C: 수동 record_task() — 프레임워크 무관, 완전 범용
    원본 에이전트 실행 → 결과 수집 → monitor.record_task()
    → 가장 범용적, 어떤 프레임워크에도 적용 가능
```

| 방식 | 코드량 | 토큰 자동 추출 | 도구 자동 추출 | 권장 상황 |
|------|--------|--------------|--------------|----------|
| @agent_eval | 1줄 | ✅ (21개 FW) | ✅ | 신규 코드 |
| Factory | 1~5줄 | 프레임워크별 | 프레임워크별 | 기존 코드 최소 변경 |
| 수동 | ~10줄/태스크 | ❌ 직접 설정 | ❌ 직접 설정 | 완전 커스텀 |

```python
from agent_evaluator import PerformanceMonitor
from agent_evaluator.decorators import agent_eval
from langchain_openai import ChatOpenAI          # langchain.chat_models 아님 (deprecated)

from langchain.agents import create_react_agent, AgentExecutor

llm = ChatOpenAI(model="gpt-4o-mini", temperature=0)
tools = [DuckDuckGoSearchRun()]
monitor = PerformanceMonitor.for_rag_evaluation(output_dir="results/")

# ── 방식 A: 데코레이터 (권장) ──────────────────────────────────
@agent_eval(monitor, task_type="qa", framework="langchain")
def lc_agent(question: str, ground_truth: str = "") -> str:
    agent_executor = AgentExecutor(agent=create_react_agent(llm, tools, prompt), tools=tools)
    result = agent_executor.invoke({"input": question})
    return result["output"]
    # → LangChain 응답에서 token_usage, tool_calls 자동 추출

# ── 방식 B: 콜백 방식 (실시간 토큰·도구 추적) ─────────────────

    monitor=monitor, task_id="task_001",
    expected_tools=["duckduckgo_search"],
)
result = agent_executor.invoke({"input": "한국의 수도는?"}, config={"callbacks": [callback]})

# ── 방식 C: Factory ────────────────────────────────────────────
from agent_evaluator.integrations.langchain_integration import create_evaluated_langchain_agent
agent = create_evaluated_langchain_agent(llm=llm, tools=tools, monitor=monitor)
```

### 품질 게이트 개념

프로덕션 배포 전에 에이전트가 최소 품질 기준을 통과하는지 자동으로 검증한다.

```
개발 → [Dev Gate] → 스테이징 → [Staging Gate] → 프로덕션
              ↓                         ↓
         빠른 피드백                종합 검증
         Layer 1만                  Layer 1+2 전체
         임계값 낮음                 임계값 높음
```

### 환경별 품질 게이트 설계

```python
from agent_evaluator import PerformanceMonitor

QUALITY_GATES = {
    "dev": {
        "task_completion_rate": 0.70,    # 개발 중 허용 낮음
        "avg_accuracy": 0.65,
        "hallucination_rate": 0.20,      # 10건 중 2건까지 허용
        "avg_latency_p95": 10.0,         # P95 10초
    },
    "staging": {
        "task_completion_rate": 0.85,
        "avg_accuracy": 0.80,
        "hallucination_rate": 0.10,
        "avg_latency_p95": 5.0,
        "tool_selection_f1": 0.75,       # Staging부터 Tool F1 체크
        "security_threat_rate": 0.05,    # 보안 위협 5% 이하
    },
    "production": {
        "task_completion_rate": 0.92,
        "avg_accuracy": 0.87,
        "hallucination_rate": 0.05,
        "avg_latency_p95": 3.0,
        "tool_selection_f1": 0.85,
        "security_threat_rate": 0.02,
        "token_efficiency": 0.8,
    }
}

def check_quality_gate(monitor: PerformanceMonitor, env: str) -> dict:
    """품질 게이트 검사"""
    gates = QUALITY_GATES[env]
    report = monitor.generate_report()
    results = {}
    passed = True

    for metric, threshold in gates.items():
        actual = report.get(metric, 0)
        ok = actual >= threshold

        results[metric] = {
            "threshold": threshold,
            "actual": actual,
            "passed": ok
        }

        if not ok:
            passed = False
            print(f"❌ {metric}: {actual:.3f} < {threshold} (임계값)")
        else:
            print(f"✅ {metric}: {actual:.3f} ≥ {threshold}")

    results["overall_passed"] = passed
    return results
```

### 실제 사용 패턴

```python
from agent_evaluator import evaluation_session

# 스테이징 품질 게이트
with evaluation_session("staging_eval") as monitor:

# 품질 게이트 검사

if not gate_results["overall_passed"]:

    exit(1)  # CI/CD 파이프라인 중단
else:
    print("✅ 스테이징 품질 게이트 통과")
```

```yaml
          AGENT_EVALUATOR_OUTPUT_DIR: ./results
        run: |
          python Evaluator_Examples/01_quality_eval.py
          python Evaluator_Examples/02_performance_eval.py
          python Evaluator_Examples/03_agentic_eval.py

      - name: Check quality gate
        run: |
          agent-eval gate results/*.json --tcr 85 --accuracy 80

      - name: Upload evaluation results
        uses: actions/upload-artifact@v4
        if: always()
        with:
          name: evaluation-results
          path: results/
          retention-days: 30

      # Layer 3는 main 브랜치 + 비용 절감을 위해 PR은 제외
      - name: Run Layer 3 evaluation (main only)
```

## 전체 과정 요약

### 5개 모듈 지식 맵

```
M1 — 기초
  └── 왜 에이전트 평가인가
  └── 3-Layer 아키텍처
  └── PerformanceMonitor + TaskResult

M2 — Layer 1 (기반 지표)
  └── TCR → 완료율
  └── Accuracy → 가중 알고리즘 (F1+Jaccard+LCS+Char)
  └── Hallucination → Rule-based vs L3 LLM 비교
  └── Quality → 5차원 레이더
  └── Latency → P50/P95/P99 퍼센타일
  └── Token Economy → I/O 비율 진단

M3 — Layer 2 (에이전틱 + 보안)
  └── Tool Call + Selection F1
  └── Retry → avg_retry_time: 재시도 태스크만 집계
  └── Coordination → overall_score 정상 계산
  └── Workflow → 퍼널 분석
  └── 보안 5종 → API 변경 이력 숙지 필수

M4 — Layer 3 (하이브리드)
  └── DeepEval → G-Eval criteria 작성법
  └── Ragas → 4지표 진단 매트릭스
  └── 레이어 선택 매트릭스
  └── Ragas 0.4.x API 변경
  └── QuickEval.for_rag() / rag_mode=True / LLMJudge

M5 — 통합 + 실무
  └── 3가지 통합 방식 (@agent_eval / Factory / 수동)
  └── 21개 프레임워크 어댑터 자동 추출
  └── 크로스 프레임워크 핸드오프 + QuickEval.compare()
  └── 품질 게이트 설계 + QuickEval.gate()
  └── GitHub Actions CI/CD
```
