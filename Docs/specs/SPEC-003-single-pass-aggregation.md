# SPEC-003: 단일 패스 집계 (46회 순회 → 1회)

**Phase:** P1 · **상태:** Draft — [SPEC-000](SPEC-000-gate-package-decomposition.md)의 REQ-2로 흡수됨 · **의존성:** 없음 (SPEC-001보다 먼저 진행 권장)

> **2026-07-02 재검토 노트**: 이 스펙의 요구사항(REQ-1~3)은 `monitor.py` 현재 위치에서 별도로 구현하지 않고, SPEC-000의 Gate별 이관 시 각 `gates/gate_x/aggregate.py` 작성 단계에서 함께 적용한다(이관과 단일 패스화를 동시에 처리해 이중 작업 방지). 이 문서는 REQ 상세 근거 자료로 유지한다.

## Context

- `agent_evaluator/core/trackers/monitor.py:2779-4064` `_compute_harness_groups` 내부에서 `for t in tasks`류 순회가 **46회** 발견됨(grep 카운트, 리팩터 착수 시 정확한 목록 재확인 필요).
- 캐싱 데코레이터(`@lru_cache`/`@cached_property`)가 전혀 없어 `generate_report()`(`monitor.py:2722`)가 호출될 때마다 이 함수 전체가 처음부터 다시 실행된다.
- 교차 참조(Gate A→B의 `avg_goal_alignment`/`avg_plan_coherence`, SLA→Gate C&D)는 **개별 태스크 순회 도중이 아니라, 순회가 끝난 뒤 스칼라 값을 조합하는 단계**에서 발생한다(`monitor.py:3841-3878` 부근의 `_g(...)` 딕셔너리 조립부). 즉 46개 순회를 병합해도 이 조합 단계의 순서(A 계산 완료 → B가 A의 결과 참조)만 보존하면 로직이 깨지지 않는다.

## Goals

- **결과값을 100% 동일하게 유지**하면서 순회 횟수만 축소한다. 이것은 알고리즘 변경이 아니라 성능 전용 리팩터다.
- 46개 지표에 필요한 러닝 합/카운트/리스트를 하나의 `for t in tasks:` 루프 안에서 동시에 축적한다.

## Non-Goals

- Gate 점수 산출 공식 자체의 변경.
- SPEC-001의 `gates/` 패키지 분리(이 스펙은 `monitor.py` 내부에서 먼저 완료하거나, `gates/` 분리와 동시 진행 가능하나 계산 순서 보존이 우선).

## Requirements

- **REQ-1**: 기존 46개 순회가 각각 만들어내는 중간 변수(리스트/합/카운트)를 식별하고, 단일 순회에서 동일한 변수를 채우도록 재작성한다.
- **REQ-2**: 순회 종료 후의 스칼라 도출 단계(Gate별 최종 점수 계산, `_g(...)` 딕셔너리 조립, A→B/SLA→C·D 교차 참조)는 **기존 순서를 그대로 보존**한다.
- **REQ-3**: 리팩터 전후 동일 입력에 대해 `_compute_harness_groups`의 반환값이 **완전히 동일**해야 한다(dict 필드 단위 비교, 부동소수점 반올림 오차 없음).

## Interface

내부 구현 전용 리팩터 — 공개 메서드 시그니처(`generate_report()`, `_compute_harness_groups(tasks)`) 변경 없음.

## Acceptance

- 기존 2,795개 테스트 전량 green.
- 대용량(10,000+ task) 합성 픽스처를 리팩터 전/후 버전에 각각 태워 `_compute_harness_groups` 출력의 JSON 직렬화 결과가 **byte 단위로 동일**한지 검증하는 회귀 테스트 추가.
- 리팩터 전/후 실행 시간 벤치마크(동일 픽스처, 동일 환경)로 순회 횟수 축소에 따른 개선폭을 기록.

## Compatibility

- 순수 내부 구현 변경이므로 공개 API·기존 테스트 영향 없음(단, REQ-3 위반 시 즉시 롤백 대상).

## Rollout

1. 46개 순회 목록을 코드에서 정확히 재추출(주석으로 원래 위치 표시하며 병합).
2. 단일 순회로 병합한 새 구현을 기존 구현과 나란히 두고(feature flag 또는 임시 이중 실행) 동일 입력에 대해 출력 diff가 0임을 CI에서 확인.
3. 검증 완료 후 기존 46-순회 구현 제거.

## Risks

- 46개 순회 중 일부가 실제로는 서로 다른 필터 조건(`if (t.extra or {}).get(...) is not None` 등)을 가지고 있어, 병합 시 조건을 잘못 합치면 특정 지표의 대상 태스크 집합이 미묘하게 달라질 수 있음 → REQ-3의 byte-diff 검증이 이 리스크의 핵심 안전장치이며, 하나라도 실패하면 병합을 되돌린다.
- SLA 표본 부족 판정(SPEC-002)과 동시 진행 시 두 변경이 같은 코드 영역을 건드리므로 병합 순서를 명확히 하고 각각 별도 커밋/PR로 분리한다.
