# AI Agent 실무 대시보드 고도화 기획안

**버전:** 1.0
**기준:** `agent-eval serve` FastAPI 대시보드 v0.5.2 위에 단계적 구현
**목적:** AI Agent 개발 및 운영 실무에서 즉시 활용 가능한 수준의 대시보드

---

## 현황 분석

### 현재 구현된 기능 (v0.5.2)
- Overview KPI 카드 (TCR, Accuracy, Hallucination, Latency, Cost, Tasks)
- Health Score 게이지 (Layer 1/2/성능/보안 가중 평균)
- Layer 1 (TCR·Accuracy·Quality·Hallucination·RAG·DeepEval)
- Layer 2 (Tool Selection·Tool Efficiency·Multi-Agent·Workflow·Retry)
- Layer 3 (DeepEval·Ragas·태스크별)
- Security (입력·출력·권한·권한 상승·공격 탐지·통합)
- Insights (알림·권고·이상치·상관관계·데이터 품질)
- Transparency (트레이스·어노테이션·감사로그)
- 파일 비교, Golden Dataset CRUD, Export (HTML/CSV/JSON)

### 실무 적용의 핵심 GAP

| 부재 기능 | 비즈니스 영향 |
|-----------|--------------|
| 배포 준비도 게이트 | "지금 스테이징에 올릴 수 있나?"를 즉시 판단 불가 |
| KPI 증감 (델타) | 개선 여부를 차트로 이동하지 않고 Overview에서 바로 파악 불가 |
| 트렌드 차트 | 반복 평가 간 추이를 한눈에 볼 수 없음 |
| 비용 예측 | 현재 Task당 비용 외에 월별 예산 영향 미표시 |
| 회귀 감지 | 이전 대비 나빠진 지표에 대한 자동 경보 없음 |
| 경영진 요약 | 팀장·의사결정자용 1페이지 요약 부재 |

## Phase 1 — 배포 준비도 & 트렌드 (즉시 실용성 ★★★)

> **구현 목표**: Overview 한 화면에서 "지금 배포할 수 있는가?"를 3초 안에 판단

### 1-1. 배포 준비도 게이트 (Deployment Readiness Gate)

Overview 최상단에 3단계 게이트 배너 추가.

```
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│ 🔬 개발 게이트    │  │ 🚀 스테이징 게이트 │  │ 🏭 프로덕션 게이트│
│                  │  │                  │  │                  │
│ ✅ TCR ≥ 80%     │  │ ✅ TCR ≥ 90%     │  │ ❌ TCR ≥ 95%     │
│ ✅ Accuracy ≥70% │  │ ✅ Accuracy ≥85% │  │ ✅ Accuracy ≥90% │
│ ✅ Hall ≤ 10%    │  │ ⚠️ Hall ≤ 5%     │  │ ❌ Hall ≤ 3%     │
│                  │  │ ✅ P95 ≤ 2s      │  │ ✅ P95 ≤ 2s      │
│ ● PASS           │  │ ● PARTIAL (3/4)  │  │ ● FAIL (3/5)     │
└──────────────────┘  └──────────────────┘  └──────────────────┘
```

**기준값 (기본, 설정에서 변경 가능):**

| 단계 | TCR | Accuracy | Hallucination | P95 Latency | Cost/task |
|------|-----|----------|---------------|-------------|-----------|
| 개발 | ≥80% | ≥70% | ≤10% | — | — |
| 스테이징 | ≥90% | ≥85% | ≤5% | ≤2s | — |
| 프로덕션 | ≥95% | ≥90% | ≤3% | ≤2s | ≤$0.01 |

### 1-2. KPI 카드 델타 표시

다음 파일이 존재할 때 KPI 카드에 이전 대비 증감 표시.

```
┌───────────────────┐
│ Task Completion   │
│      94.2%        │
│  ▲ +2.1%  (이전)  │  ← 이전 파일 대비 증감
│  ✅ 임계값 통과   │
└───────────────────┘
```

- 개선: ▲ 초록
- 악화: ▼ 빨강
- 변화 없음: ─ 회색

### 1-3. 트렌드 차트 (파일 2개 이상 시 표시)

Overview 하단에 자동 표시.

```
  지표 트렌드 (최근 N회 평가)

  100% ─────────────●─────●
   90% ──────●────────         ← TCR
   80%        ●────              ← Accuracy
         run1  run2  run3  run4

  현재 파일 강조 표시 (●)
  임계값 기준선 점선 표시 (─ ─)
```

- X축: 파일명/타임스탬프 (오래된 순)
- Y축: TCR%, Accuracy% (0~100)
- 별도 우측 Y축: P95 Latency (초)
- 파일 개수 제한 없음, 가장 최근 10개만 표시

## Phase 2 — 비용 예측 & 회귀 감지 (운영 실용성 ★★★)

> **구현 목표**: 프로덕션 운영 중 이상 즉시 감지 + 비용 예산 관리

### 2-1. 비용 예산 추적 패널

Performance → Cost 탭 하단에 추가.

```
  💰 비용 예측 패널
  ─────────────────────────────────────────────────
  현재 Task당 비용:  $0.0042
  일일 추정 (1000 tasks): $4.20
  월간 추정 (30,000 tasks): $126.00

  예산 설정: [  $200  ] /월
  현재 소진율: ████████░░  63%  ← 월 기준
  예산 초과 예상일: 없음 ✅
```

### 2-2. 회귀 감지 알림

파일 선택 시 이전 파일 대비 자동 분석.

```
  ⚠️ 이번 평가에서 회귀된 지표 (이전 대비)
  ─────────────────────────────────────────────────
  🔴 Accuracy: 87.1% → 84.3%  ▼ -2.8%  (목표: ≥85%)
  🟡 Hallucination: 3.2% → 4.1%  ▲ +0.9%  (허용: ≤5%)
  🟡 P95 Latency: 2.1s → 2.8s  ▲ +0.7s  (목표: ≤2s)
```

### 2-3. 스프린트 비교 뷰

파일 비교 섹션 상단에 "스프린트 요약" 패널 추가.

```
  📈 개선 요약: v20240316 → v20240317
  ─────────────────────────────────────────────────
  개선됨 (2)  TCR ▲+2.1%,  Tool Selection ▲+2.8%
  악화됨 (3)  Accuracy ▼-1.2%,  Hallucination ▲+0.4%,  Cost ▲+10.5%
  동일 (2)    Quality,  Security

  종합 판정: ⚠️  혼재 — 주요 지표 추이 주시 필요
```

## Phase 3 — 팀 & 보고서 자동화 (협업 실용성 ★★☆)

> **구현 목표**: 팀 전체가 평가 결과를 공유하고 액션을 관리

### 3-1. 경영진 요약 리포트 (Executive Summary)

Export 섹션에 새 탭 추가.

```
  📄 경영진 요약 (1페이지)
  ─────────────────────────────────────────────────
  AI Agent 평가 결과 요약 — 2024-03-17

  전체 건강도: 83/100 [GOOD]

  주요 지표:   TCR 94.2%  |  Accuracy 87.1%  |  Cost $1.024/run
  전회 대비:   ▲ 개선 2개  |  ▼ 악화 3개

  즉시 대응:   P95 Latency 초과 (2.81s > 2.0s 목표)
  다음 목표:   Accuracy 90% 달성 예상 일정: 2024-03-24

  [PDF 다운로드]  [Slack 공유]  [링크 복사]
```

### 3-2. 커스텀 KPI 설정

Settings에서 비즈니스 목표별 KPI 프리셋 저장.

```
  KPI 프리셋 관리
  ─────────────────────────────────────────────────
  [고객지원 봇]  [코드 생성 에이전트]  [RAG 검색 에이전트]  [+ 새 프리셋]

  선택 프리셋: 고객지원 봇
  ─────────────────────────────────────────────────
  TCR 임계값:   90%    (고객지원은 완료율 최우선)
  Accuracy:     80%    (참고 답변 수준)
  Hallucination: 3%   (신뢰도 중요)
  Latency P95:  1.5s  (UX 반응성)
  Cost/task:    $0.005 (대량 처리 고려)
```

### 3-3. 알림 자동화 연동

Settings에 Webhook/알림 설정 추가.

- 임계값 위반 시 Slack Webhook 알림
- 파일 추가 감지 시 이메일/슬랙 알림
- 회귀 감지 시 GitHub Issues 자동 생성 (선택)

## 기술 노트

### Phase 1 구현 전략

- **배포 게이트**: 순수 Alpine.js computed 함수 — 새 API 불필요
- **KPI 델타**: `files` 메타 배열 활용 (이미 tcr/accuracy/avg_latency/total_cost 포함)
- **트렌드 차트**: `files` 메타 배열 → Plotly line chart, `renderAll()` 내 추가

### 데이터 흐름 (Phase 1)

```
/api/results (기존)
  └─► files[]  →  prevFile()  →  delta 계산  →  KPI 카드 델타
                →  trArr()    →  트렌드 차트 렌더링

data (기존)   →  deployGates()  →  게이트 배너
```

---

*Phase 1은 기존 API 변경 없이 프론트엔드만 수정으로 구현 가능.*
