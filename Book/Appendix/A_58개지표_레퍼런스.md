### 1. Task Completion Rate (TCR)

> ↗ **상세 설명**: [Chapter 4 §4.2 — Group A Tracker](../Part_II_지표시스템/Chapter_04_GroupA_목표달성.md)

**계산 공식**

```
TCR = sum(completion_score) / task_count × 100
```

`completion_score`는 `TaskResult` 필드 (0.0~1.0). `create_taskresult()` 사용 시 자동 계산된다.

> **task_type별 완료 판정 (v0.8.0+)**
> - `code_generation`/`coding`: AST 파싱 성공 시 1.0
> - `tool_use`: `tool_calls` 비어 있으면 0.6 (부분 완료)
> - 기타: 응답 길이 ≥ 10자이면 1.0

**권장 임계값**

| 등급 | 범위 |
|------|------|
| 우수 | 95% 이상 |
| 양호 | 85~95% |
| 보통 | 70~85% |
| 개선 필요 | 70% 미만 |

**리포트 키**

```python
report.task_completion_rate                         # float (0~100)
report.to_dict()["tcr_data"]["success_rate"]        # float (0~1)
report.to_dict()["tcr_data"]["total_tasks"]         # int
report.to_dict()["tcr_data"]["successful_tasks"]    # int
```

### 2. Accuracy

> ↗ **상세 설명**: [Chapter 4 §4.2 — Group A Tracker](../Part_II_지표시스템/Chapter_04_GroupA_목표달성.md)

**계산 공식 — QA (가중 조합)**

```
Accuracy = 0.4 × TokenOverlapF1 + 0.3 × Jaccard + 0.2 × LCS + 0.1 × CharSimilarity
```

- TokenOverlapF1: F1 기반 토큰 매칭 (Precision × Recall 조화평균)
- Jaccard: 집합 교집합 / 합집합
- LCS: Longest Common Subsequence 비율
- CharSimilarity: Levenshtein 거리 기반 문자 유사도 (문자 순서 반영)

**계산 공식 — Code**

```
Accuracy = 1.0  (실행 결과 일치)
         = 0.0  (불일치)
```

AST 비교 → 정규화 비교 순으로 fallback.

**권장 임계값**

| 등급 | 범위 |
|------|------|
| 우수 | 90% 이상 |
| 양호 | 80~90% |
| 보통 | 70~80% |
| 개선 필요 | 70% 미만 |

**주의**: `ground_truth`를 빈 문자열 또는 `None`으로 전달하면 accuracy_score가 0.0이 된다.

**리포트 키**

```python
report.overall_accuracy                                  # float (0~100)
report.to_dict()["accuracy_data"]["overall_accuracy"]    # float (0~100)
report.to_dict()["accuracy_data"]["median_accuracy"]     # float
```

### 3. Response Quality

> ↗ **상세 설명**: [Chapter 4 §4.2 — Group A Tracker](../Part_II_지표시스템/Chapter_04_GroupA_목표달성.md)

**5차원 평가 (각 0~5점)**

| 차원 | 가중치 | 계산 방식 |
|------|--------|----------|
| Relevance | 25% | 요청 단어 ∩ 응답 단어 / 요청 단어 수 × 5 |
| Completeness | 25% | expected_elements 중 응답에 포함된 비율 × 5 |
| Accuracy | 20% | ground_truth 기반 피드백 (기본값 4.0) |
| Clarity | 15% | 단어 수 + 구조 유무 기반 |
| Usefulness | 15% | 기본값 4.0 |

**계산 공식**

```
Quality Score = Σ(dimension_score × weight)    범위: 0~5점
```

**권장 임계값**

| 등급 | 범위 |
|------|------|
| A (우수) | 4.5 이상 |
| B (양호) | 4.0~4.5 |
| C (보통) | 3.5~4.0 |
| D (미흡) | 3.0~3.5 |
| F (개선 필요) | 3.0 미만 |

**리포트 키**

```python
report.to_dict()["quality_data"]["avg_total_score"]        # float (0~5)
report.to_dict()["quality_data"]["grade_distribution"]     # {"A": n, "B": n, ...}
```

### 6. Hallucination Rate (규칙 기반)

> ↗ **상세 설명**: [Chapter 6 §6.2 — Group C Tracker](../Part_II_지표시스템/Chapter_06_GroupC_신뢰성.md)

**활성화 방법** (기본값 False — opt-in 필수)

```python
monitor = PerformanceMonitor(enable_hallucination_detection=True)
# 또는
monitor = PerformanceMonitor.for_rag_evaluation()  # 자동 활성
# 또는 데코레이터에서 임시 활성
@agent_eval(monitor, task_type="information_retrieval", enable_hallucination_detection=True)
```

**탐지 방법**

| 방법 | 조건 | 심각도 |
|------|------|--------|
| Unsupported Claim | 응답 문장의 컨텍스트 단어 중첩률 < 30% (5단어 이상) | Medium |
| Numerical Inconsistency | 응답 숫자가 컨텍스트 / ground_truth에 없음 | High |

**계산 공식**

```
Hallucination Rate = 환각 플래그 작업 수 / 컨텍스트 있는 작업 수 × 100
```

규칙 기반 탐지 정확도: 70~80%, 오버헤드: < 5ms. 외부 평가 라이브러리 DeepEval Hallucination Score (LLM 기반, 90~95% 정확도)와 방향이 반대임에 주의한다 (규칙 기반: 낮을수록 좋음 / DeepEval: 높을수록 좋음).

**권장 임계값**

| 등급 | 범위 |
|------|------|
| 우수 | 1% 미만 |
| 양호 | 1~5% |
| 보통 | 5~10% |
| 위험 | 10% 이상 |

**리포트 키**

```python
report.hallucination_rate                                          # float | None
report.to_dict()["hallucination_data"]["overall_rate"]            # float (0~1)
report.to_dict()["hallucination_data"]["tasks_with_hallucinations"] # int
```

### 9. Tool Selection Accuracy

> ↗ **상세 설명**: [Chapter 9 §9.2 — Group F Tracker](../Part_II_지표시스템/Chapter_09_GroupF_다중에이전트.md)

**계산 공식 — F1 기반**

```
TP = |expected_tools ∩ actual_tools|
FP = |actual_tools - expected_tools|
FN = |expected_tools - actual_tools|

precision = TP / |actual_tools|   (actual_tools가 공집합이면 0)
recall    = TP / |expected_tools| (expected_tools가 공집합이면 0)
F1        = 2 × precision × recall / (precision + recall)
accuracy  = F1 × 100 (%)
```

**권장 임계값**: 90% 이상 우수 / 80~90% 양호 / 70% 미만 개선 필요

**활성화 방법**: `expected_tools` 필드를 `TaskResult`에 포함하거나 `evaluate_selection()` 직접 호출

### 10. Agent Coordination

> ↗ **상세 설명**: [Chapter 9 §9.2 — Group F Tracker](../Part_II_지표시스템/Chapter_09_GroupF_다중에이전트.md)

**계산 공식**

```
Coordination Score = success_rate×0.5 + diversity_score×0.3 + balance_score×0.2

success_rate    = 성공 상호작용 / 전체 상호작용 × 100
diversity_score = min(고유 에이전트 수 / 5, 1.0) × 10
balance_score   = 상호작용 유형 수 / 3 × 10
```

허용 interaction_type: `delegation`, `communication`, `collaboration`

**권장 임계값**: 8점 이상 우수 / 6~8점 양호 / 4점 미만 개선 필요

**리포트 키**

```python
report.to_dict()["coordination_score"]    # float (0~10)
```

### LLM Judge — 5종 기본 (기본 설치에 포함) — v0.7.5+ · faithfulness/커스텀 차원 확장 — v0.7.6+

> ↗ **상세 설명**: [Chapter 10 §10.2 — Group G Tracker](../Part_II_지표시스템/Chapter_10_GroupG_운영관측성.md)

`LLMJudge`는 ground_truth 없이 응답을 5차원으로 자동 채점하며, RAG 컨텍스트가 있으면 Faithfulness를 추가하고, `judge_criteria`로 무제한 커스텀 차원을 추가할 수 있다.

| 지표 | 설명 | 범위 | 조건 |
|------|------|------|------|
| Completeness | 응답이 질문을 얼마나 완전히 다루는가 | 0~1 | 기본 포함 |
| Relevance | 응답이 질문에 얼마나 관련이 있는가 | 0~1 | 기본 포함 |
| Factual Consistency | 응답 내 사실 일관성 | 0~1 | 기본 포함 |
| Toxicity | 독성 콘텐츠 점수 (낮을수록 좋음) | 0~1 | 기본 포함 |
| Bias | 편향 콘텐츠 점수 (낮을수록 좋음) | 0~1 | 기본 포함 |
| **safety_score** | 안전성 종합 `(10 - toxicity - bias) / 10` | 0~1 | 기본 포함, 1.0 = 완전 안전 |
| **Faithfulness** | 응답이 컨텍스트에 충실한가 (v0.7.6+) | 0~5 | `rag_mode=True + llm_judge=LLMJudgeConfig()` |
| **커스텀 차원** | 서비스 특화 기준, G-Eval 대체 (v0.7.6+) | 0~5 | `llm_judge=LLMJudgeConfig(criteria=[...])` 설정 시 |

```python
# 기본 활성화
@agent_eval(monitor, task_type="qa", llm_judge=LLMJudgeConfig(model="claude-sonnet-4-6"))

# Faithfulness (Ragas 대체)
@agent_eval(monitor, task_type="information_retrieval", rag_mode=True, llm_judge=LLMJudgeConfig())

# G-Eval 커스텀 기준 (DeepEval 대체)
@agent_eval(monitor, task_type="qa",
            llm_judge=LLMJudgeConfig(criteria=["professionalism", "empathy", "clarity"]))
```

## Harness Config 공통 패턴

### `fail_on_violation` 설정 가이드

| 상황 | 권장값 | 이유 |
|------|--------|------|
| 배포 필수 기준 (TCR, SLA, 보안) | `True` | 기준 미달 시 배포 차단 |
| 모니터링 목적 (재현성, 비용) | `False` | 로그·경보만 발생 |
| 개발 초기 단계 | `False` | 기준 측정 후 임계값 결정 |
| 프로덕션 안정화 후 | `True` | 회귀 방지 |

### 빠른 시작 — 최소 Harness Config 세트

```python
# 모든 에이전트에 적용할 수 있는 3개 Config 최소 세트
from agent_evaluator import (
    agent_eval, PerformanceMonitor,
    InstructionConfig, SLAConfig, ThreatSeverityConfig,
)

monitor = PerformanceMonitor(output_dir="results/")

@agent_eval(
    monitor, task_type="qa",
    instructions=InstructionConfig(min_completion_rate=0.85, fail_on_violation=True),
    sla=SLAConfig(max_p95_latency=5.0, fail_on_violation=True),
    threat_severity=ThreatSeverityConfig(max_severity="high", fail_on_violation=True),
)
def my_agent(question: str, ground_truth: str = "") -> str: ...
```

### HarnessEvaluationGate — 종합 배포 판정

```python
from agent_evaluator.decorators import HarnessEvaluationGate

# 모든 Config를 종합한 배포 판정
gate = HarnessEvaluationGate(
    configs=minimum_harness,
    require_all_pass=True,     # 모든 Config 통과 필요
    allow_partial_pass=False,  # 부분 통과 허용 안 함
)

result = gate.evaluate(monitor.generate_report())
# → {"passed": True/False, "violations": [...], "summary": {...}}

if not result["passed"]:
    print(f"배포 차단: {result['violations']}")
    sys.exit(1)
```
